# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal Hyprland/Arch desktop configuration, built on top of [ML4W](https://github.com/mylinuxforwork/dotfiles). There is no build, test, or lint step — every file here is a live config consumed by a running desktop.

## Layout

- `dotfiles/` — mirrors `$HOME`. `dotfiles/.config/hypr` is what lives at `~/.config/hypr`, etc.
- `ml4w/` — git submodule pinning pristine upstream ML4W. It is a **reference copy only**, never deployed. Use it to diff local changes against upstream or to pull in upstream updates:
  `diff -rq dotfiles/.config/ml4w ml4w/dotfiles/.config/ml4w`

### Deployment: symlinks, not a copy step

Each top-level entry under `dotfiles/` is individually symlinked into `$HOME` (e.g. `~/.config/hypr -> ~/.mydotfiles/dotfiles/dotfiles/.config/hypr`). Consequences:

- Editing a file in this repo takes effect immediately — no install/sync command exists.
- Editing `~/.config/<x>/...` for an already-linked `<x>` edits the repo. Check `git status` after desktop-side changes.
- Adding a **new** top-level config dir requires creating the symlink by hand; nothing does it automatically.

## Theming pipeline (matugen)

All colors across the desktop are generated from the current wallpaper. Never hand-edit a generated color file — the next wallpaper change overwrites it.

Flow: `ml4w-wallpaper <image>` → `matugen image ... -m dark|light` → renders every template in `.config/matugen/config.toml` → `post_hook` reloads the affected app (`hyprctl reload`, `pkill -SIGUSR1 kitty`, `pkill -USR2 btop`, …).

- **Edit here:** `dotfiles/.config/matugen/templates/*` and the input→output mapping in `dotfiles/.config/matugen/config.toml`.
- **Generated (all gitignored, listed at the bottom of `.gitignore`):** `hypr/colors.{conf,lua}`, `kitty/colors-matugen.conf`, `waybar/colors.css`, `swaync/colors.css`, `walker/colors.css`, `rofi/colors.rasi`, `gtk-{3,4}.0/colors.css`, `yazi/theme.toml`, `btop/themes/matugen.theme`, `ohmyposh/colors.json`, `quickshell/CustomTheme/Theme.qml`, `quickshell/overview/common/Appearance.colors.qml`, `ml4w/colors/*`.
- `quickshell/CustomTheme/Theme.qml` being generated is why QML must read colors through `Theme`, never as literals.

## Hyprland config is Lua, not hyprlang

Hyprland is driven by [hyprmod](https://github.com/BlueManCZ/hyprmod) (installed via `.config/ml4w/scripts/ml4w-install-hyprmod`), which exposes a global `hl` API (`hl.bind`, `hl.monitor`, `hl.on`, `hl.exec_cmd`, `hl.dsp.*`).

- Entry point `hypr/hyprland.lua` just `require`s the modules under `hypr/conf/` (input, autostart, keybinding, windowrule, …); shared helpers live in `hypr/lib/`.
- `hypr/.luarc.json` declares `hl` as a global and points lua_ls at `/usr/share/hypr/stubs` — keep it in sync if new globals appear.
- `hypr/monitors.lua` is generated by nwg-displays; do not hand-edit.
- Companion daemons still use classic hyprlang: `hyprlock.conf`, `hypridle.conf`, `hyprsunset.conf`.
- `.conf` siblings (`colors.conf`, `monitors.conf`, `workspaces.conf`) are leftovers from the pre-hyprmod setup and are not read by `hyprland.lua`.

## Quickshell (the desktop shell)

`~/.config/quickshell` is the main QML config, launched as bare `qs` by `.config/ml4w/scripts/ml4w-autostart`. Two extra Quickshell instances run from separate `-p` paths: `quickshell/overview` (workspace overview, upstream third-party module with its own README) and the ML4W settings app under `~/.local/share/ml4w-dotfiles-settings`.

- `quickshell/shell.qml` is the `ShellRoot`: one window component per app dir (`WelcomeApp`, `PowerApp`, `SidebarApp`, `CalendarApp`, `WallpaperApp`), plus a `Variants { model: Quickshell.screens }` that instantiates one `WaybarApp/WaybarWindow` per monitor.
- `WaybarApp/` is a native replacement for waybar (three glass islands, ml4w-glass look); audio/bluetooth/network modules use `Quickshell.Pipewire/Bluetooth/Networking` directly rather than shelling out. See `quickshell/README.md` for the module list and IPC surface.
- The legacy `waybar/` config is still in the tree but its launch is commented out in `hypr/conf/autostart.lua`.
- `StatusbarApp/` is the superseded predecessor of `WaybarApp/`; `WaybarApp` deliberately reuses its IPC target (`statusbar`) and settings file so the SidebarApp toggle keeps working.

Reload after a QML edit: `killall qs && qs &`, or targeted IPC — `qs ipc show` lists handlers, e.g. `qs ipc call statusbar reload`, `qs ipc call theme-manager reload`.

## ML4W scripts and settings

- `.config/ml4w/scripts/` and `.config/ml4w/bin/` hold the shell helpers bound to keys and menus (`ml4w-wallpaper`, `ml4w-power`, `ml4w-screenshot`, `ml4w-toggle-*`, …). Many are locally modified forks of the upstream versions in `ml4w/dotfiles/.config/ml4w/scripts/` — diff before overwriting.
- `.config/ml4w/settings/` is user-facing runtime state (chosen browser, blur amount, wallpaper effect) that **is tracked in git**, so flipping a setting in the GUI shows up as a repo diff.
- Keybindings reference these by absolute path (`~/.config/ml4w/scripts/...`); they are not on `PATH`.

## Gotchas

- Shell configs are split three ways: `dotfiles/.zshrc`, `dotfiles/.bashrc`, and `.config/fish/` (the actual daily shell — `conf.d/*.fish` numbered load order, `functions/`, `completions/`).
